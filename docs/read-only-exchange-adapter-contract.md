# Read-only Exchange Adapter Contract

## هدف

تعریف مرز مشترک برای adapterهای دادهٔ صرافی‌ها، بدون هرگونه قابلیت ارسال سفارش، معامله یا endpoint معاملاتی.

## الزامات

هر adapter باید فقط دادهٔ بازار را بخواند و یک `NormalizedSnapshot` معتبر برگرداند.

- فقط endpointهای عمومی و read-only مجاز هستند.
- کلید API، secret، امضای درخواست و دسترسی حساب نباید لازم باشد.
- متدهای سفارش‌گذاری، لغو سفارش، اجرای معامله، موجودی و موقعیت معاملاتی نباید وجود داشته باشند.
- داده‌ها باید دارای provenance، زمان دریافت و زمان دسترس‌پذیری باشند.
- adapter نباید داده‌ای را که در زمان `as_of` در دسترس نبوده، وارد snapshot کند.
- خطاهای شبکه، پاسخ نامعتبر و دادهٔ ناقص باید به وضعیت کیفیت مناسب تبدیل شوند و نباید silently نادیده گرفته شوند.

## رابط پیشنهادی

```python
class ReadOnlyDataSource(Protocol):
    def fetch_snapshot(
        self, *, as_of: datetime | None = None
    ) -> NormalizedSnapshot:
        ...
```

## مرز مسئولیت

adapter مسئول دریافت، نرمال‌سازی و ثبت provenance است؛ منطق سیگنال، تصمیم‌گیری، مدیریت ریسک و اعلان‌ها خارج از adapter باقی می‌مانند.

## معیار پذیرش

- تست قرارداد مشترک برای هر adapter وجود داشته باشد.
- تست عدم وجود قابلیت معاملاتی وجود داشته باشد.
- تست deterministic بودن خروجی با دادهٔ ثابت وجود داشته باشد.
- تست PIT/no-lookahead برای timestampها وجود داشته باشد.
- هیچ تست یا پیاده‌سازی‌ای به endpoint معاملاتی وابسته نباشد.
