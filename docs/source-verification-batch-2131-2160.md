## Reports

2131. Bybit public WebSocket Ticker uses both `snapshot` and `delta` message types for derivatives; an absent response parameter means its value has not changed.
2132. Bybit documents Spot and Option Ticker messages as `snapshot` only.
2133. Bybit documents derivative and option ticker push frequency as 100ms and Spot ticker push frequency as 50ms.
2134. Bybit Ticker `ts` is the millisecond timestamp generated by the system for the data message.
2135. Bybit Ticker `cs` is documented as a cross-sequence integer and can be retained as transport/order information rather than interpreted as a price timestamp.
2136. Bybit Ticker `type` identifies whether the message is `snapshot` or `delta` for streams where delta updates are used.
2137. Bybit Ticker `lastPrice` is the latest-price field for derivative ticker data.
2138. Bybit Ticker `markPrice` and `indexPrice` are separately documented fields and must not be conflated.
2139. Bybit Ticker `openInterest` represents open-interest size for both sides, while `singleOpenInterest` is a separately documented single-side field.
2140. Bybit Ticker `nextFundingTime` is a millisecond timestamp and `fundingRate` is the funding-rate field.
2141. Bybit Ticker `deliveryTime` is applicable to expired futures and is documented as a UTC datetime field.
2142. Bybit Ticker `predictedDeliveryPrice` is documented as having a value 30 minutes before delivery.
2143. Bybit public WebSocket Trade messages are pushed in real time after trades and use the `publicTrade.{symbol}` topic.
2144. Bybit public WebSocket Trade `ts` is the millisecond timestamp generated by the system for the data message.
2145. Bybit public WebSocket Trade records are sorted by the time the trade was matched in ascending order.
2146. Bybit public WebSocket Trade field `T` is the millisecond timestamp when the order is filled.
2147. Bybit public WebSocket Trade field `S` identifies the taker side as `Buy` or `Sell`.
2148. Bybit public WebSocket Trade fields `v` and `p` represent trade size and trade price respectively.
2149. Bybit public WebSocket Trade documents `seq` as a cross sequence; it is not itself the trade-match timestamp.
2150. Bybit notes that Futures and Spot can contain up to 1024 trades in one public-trade message, and multiple messages can share the same `seq`.
2151. Bybit documents that PreLaunch contracts have no public-trade feed until the `ContinuousTrading` stage.
2152. Bybit REST Recent Public Trades covers Spot, USDT contracts, USDC contracts, Inverse contracts, and Options.
2153. Bybit REST Recent Public Trades requires `category`; symbol is required for Spot, linear, and inverse requests, while it is optional for Options.
2154. Bybit REST Recent Public Trades supports `limit` from 1–60 for Spot and 1–1000 for the other categories, with documented defaults of 60 and 500 respectively.
2155. Bybit public WebSocket market-data connections use separate public endpoints for Spot, linear, inverse, spread, RFQ, and options streams.
2156. Bybit's documented WebSocket order-entry endpoint is separate from the public market-data endpoints; it requires authentication and is outside this project's execution boundary.
2157. Bybit V5 documentation separates market-data paths under `/v5/market/` from order, position, account, and asset modules; market-data documentation does not by itself authorize execution.
2158. Bybit Server Time returns `timeSecond` and `timeNano` as server timestamps and documents possible latency or temporary delivery delays during extreme market volatility.
2159. The 2026-09-10 Bybit V5 changelog records that Instruments Info added support for `baseCoin=All` for Options; this is a documented API change and not a strategy rule.
2160. The current official V5 changelog also contains new RWA stock order-related interfaces dated 2026-09-16; those interfaces are unrelated to this futures signal project's market-data scope and are not added to the source set or execution surface.
